NutriGo Data Visualisation

Rules for every chart, stat and meter in NutriGo, derived from the charts in the Claude Design export and checked with a colour-blind validator. Tokens: tokens.json. Components: index.html. Charts are hand-built inline SVG; there is no chart library (Ponytail, ADR-0003).

02 · Colour by job

Identity colours come from the semantic tokens; nothing is cycled

Macros (categorical, fixed order)

kcalcarbsproteinfat

Order is always kcal → carbs → protein → fat, in lists, tiles, bars and tooltips.

Food categories (categorical, fixed order)

GrainsVeggiesProteinFruitsDairyOthers

Six is the ceiling. A 7th category folds into Others, never a new colour. The colour follows the category, never its rank.

Magnitude (sequential)

A single hue (orange), light → dark. Used for a single-series column chart when one bar is highlighted (the peak in Expense Overview).

Target state

within targetover target ▲remaining

proposed The design has no over-target state. Over target: the fill stays full, the ring or bar switches to orange, and the label says "+120 kcal over" with ▲. The state is never shown by colour alone.

03 · Non-negotiable rules

Applied to every chart

Identity never by colour alone

  • ≥ 2 series: a legend is always present, and ≤ 4 series are also labelled directly
  • Macro tiles and bars always carry their word ("Carbs"), not just a letter or colour
  • Donut and stacked bar: the legend shows name, value and %
  • Texture: the design's hatch (45°) is available as the backup channel

Marks

  • Columns ≤ 24 px wide, 4 px rounded data end, square at the baseline
  • 2 px surface-coloured gap between touching segments or bars
  • Lines 2 px, round caps; markers ≥ 8 px with a 2 px surface ring
  • Gridlines are 1 px solid --color-line; axis text is --color-muted
  • One y-axis only. Never dual axes

Text

  • Values and labels use text tokens (ink, muted), never the series colour
  • kcal as integers with a thin space: 1 240 kcal; grams as integers: 35 g
  • EUR with 2 decimals; the locale is set once in a shared formatter
  • Estimated values prefixed "~" (e.g. ~€1.00)

Interaction & access

  • Every bar, segment and point has a hover/tap tooltip with the exact value; the hit area is larger than the mark
  • Each chart has a visually hidden <table> (or a "Show as table" toggle) with the same data
  • SVG has role="img" + aria-label summarising the takeaway
  • Filters sit in one row above the chart (select pill)
  • Respect prefers-reduced-motion: no ring animation

Empty & edge states

  • No data: a placeholder with the reason and the action ("Plan meals to see nutrition")
  • Target not set: show totals without a ring and link to Targets
  • 0 %: the track only, with a "0 of 325 g" label
  • Over 100 %: the fill caps at 100 % and the label shows the overshoot

Is it even a chart?

  • One number = a stat tile (recipe macros, KPI tiles)
  • A 2-slice comparison = a sentence ("1 750 of 2 990 kcal eaten")
  • Close values (±5 %) = bars, never a donut

05 · Implementation

How charts are built in the app

  • Hand-written React + inline SVG components in design-system/organisms/charts/: Ring, ColumnChart, Donut, StackedBar, Legend, ChartTable. Adding a chart library needs an ADR.
  • Colours come from semantic.* tokens via CSS variables. Components never receive hex values.
  • Geometry (arc lengths, scales, over-target flags) is pure functions in packages/shared/chart-math.ts, unit-tested.
  • Every chart component has a playground page with the states: empty, 0 %, typical, 100 %, over target, and 1 / max categories.
  • Screenshot tests at 390 px and 1280 px.
