02 · Semantic colour

One meaning, one colour, everywhere

The export is inconsistent: recipe-card pills colour carbs green and protein yellow, and the Dashboard's macro bars are all green. The mapping below is taken from the Design System page (stat chips) and confirmed by Healthy Menu and Recipe Details, so it is canonical. The other variants are treated as design bugs.

Macros
Calories450 kcal Carbs40 g Protein35 g Fat12 g

Units are always g, not "gr" (the export mixes both).

Meal slots (order: breakfast, lunch, snack, dinner)
Breakfast Lunch Snack Dinner

Snack is neutral grey (Meal Plan). The Healthy Menu's green Snack pill is a deviation.

Food categories (grocery aisles)
Grains Veggies Protein Fruits Dairy Others

From the Design System roles and the Grocery Category legend. The Expense Breakdown donut labels green as "Protein", which is a deviation.

Status
Eaten / purchased Planned Next meal
Purchased Pending

A status is never shown by colour alone: it always has an icon or a label.

10 · Layout & mobile (derived, pending validation)

Mobile-first, from the design's own mobile rules

The export is desktop-first (1600 px). Only Dashboard and Meal Plan have phone variants. The other phone screens follow the rules those two variants state: "only the grid changes", one column, the same tokens and atoms, a 5-item tab bar, 44 px hit targets, and secondary content moved behind the menu. Each derived screen is validated in /playground before use.

Rules proposed
  • <768 px: one column, bottom tab bar, page title in a top bar (from Dashboard Mobile)
  • 768–1199 px: one wider column; cards in 2 columns where they fit
  • ≥1200 px: 252 px sidebar + main; ≥1440 px adds the 340 px aside
  • Tab bar (5): Today · Recipes · Plan · Groceries · Targets. This changes the design's Dashboard · Menu · Plan · Progress · Profile, because Progress and Profile are out of scope
  • Tables become grouped lists on mobile (Grocery table → list per category)
  • The 7-day grid becomes WeekStrip + DayMealsPanel (from Meal Plan mobile)
  • Hit targets ≥ 44 px, and no reading text < 12 px on mobile
  • Safe-area insets for an installed PWA (env(safe-area-inset-bottom) under the tab bar)

12 · Removed patterns

In the export, deliberately not built

Multi-user / marketing
  • Logout, UserMenu, Avatar, "Member" role (no auth, ADR-0002)
  • PromoBanner "Claim FREE 1-month"
  • Footer copyright and social links
  • Notification bell + dot
  • Messages nav item + badge
Social
  • Reviews, "by 125 people"
  • Popular Menu
  • Top authors, trending tags
Out-of-scope tracking
  • Weight ruler + gauge, weight line chart
  • Steps hatch bar, sleep bars, water bar
  • Workout progress cards, exercises
  • Burned calories (no activity data)
